Data Preprocessing and Advanced SQL

Why dirty data wrecks analysis, a checklist of the common problems and their fixes, and the SQL that does the cleaning, including JSON. Practice runs on the GlassDoor data-jobs data used in class.

Garbage in, garbage out. Poor input data gives poor results, however clever the analysis. Preprocessing is the step between "I have data" and "I can trust it". Prepare & Process: the second phase of the analytics process.

Why What bad data costs

Finance
  • Flawed credit-scoring data
  • High-risk loans approved, more defaults
Marketing
  • Campaign built on uncleaned customer data
  • Wrong audience, wasted budget, low conversion
Retail
  • Sales data with missing values and outliers
  • Stock-outs or overstock

Checklist Problems and fixes

ProblemTypical exampleUsual fixes
Constraint issuesWrong data type; a value outside a valid range; duplicate rowsConvert the type; fix the typo; cap the value, or set it to missing and impute; drop if very few rows; keep one of exact duplicates, merge near-duplicates
Text and category inconsistency"USA", "U.S.", "usa"; wrong length; stray spacesRemap to one category name; infer from other columns; standardize formatting; drop only when very few rows
Unit and date inconsistencyMetres vs feet; two date formatsStandardize units and date formats; drop rows you cannot make sense of
Missing dataBlank, NULL, or a placeholder such as -1Impute with median or mean; model-based imputation; collect new data; keep as "Unknown"
OutliersA 500K salary among 50–100K onesInvestigate first: error or real? Then cap, drop, or keep

"Drop" appears on every row but always with the condition when the share of affected rows is very small. Count before you delete.

Method Three steps for the case study

  1. Plan. List the business questions, draw an issue tree, then check each column against the questions and write the checklist.
  2. Process with SQL. One CTE per fix so each step is easy to test.
  3. Validate. Row count, duplicates, remaining bad values, distributions before vs after.

SQL toolbox Cleaning functions you already know

  • CASE WHEN to remap values: '-1' to 'Unknown', titles to seniority levels.
  • LIKE '%text%' with LOWER() to find keywords and build 0/1 flag columns.
  • REPLACE, SUBSTRING, CHARINDEX, LEFT, LEN, CAST to split and convert text.
  • SELECT DISTINCT to drop exact duplicate rows.

Advanced JSON in a column

Some columns hold a small JSON document: {"Industry": "Insurance Carriers", "Sector": "Insurance", "Revenue": "..."}. T-SQL reads one key with JSON_VALUE(column, '$.Industry').

Other dialects: JSON_EXTRACT (MySQL), JSON_EXTRACT_SCALAR (BigQuery). Same idea, different name.

Watch out Mistakes while cleaning

  • Missing hides as a value. In GlassDoor, -1 means "unknown" in 6 columns. AVG(Founded) with -1 inside is wrong, and a NULL check will not find it.
  • A join can multiply rows. The company-info table repeats each company, so a naive join returns 1,760 rows from 672. Always compare row counts before and after.
  • A default bucket can hide the problem. The seniority CASE sends 559 of 672 titles to "Specialist" because the title had no level keyword. That is a design choice, not a finding.
  • Outliers are not errors by default. Ask what caused the value before you remove it.
