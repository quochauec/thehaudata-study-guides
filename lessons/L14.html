Dashboard Design and DAX

Recap the dashboard design checklist, then learn DAX: calculated columns against measures, ratios, time intelligence and filters. Each formula sits next to the T-SQL that checks it, on AdventureWorks.

DAX turns a clean model into the numbers on the page: totals, ratios, growth, shares. Design decides which of those numbers each audience sees. Try the workbench in tab 3.

What DAX

Data Analysis Expression: a collection of functions, operators and constants used in formulas to calculate and return values. It creates new information from the data already in your model.

Why Flexible metrics

DAX handles everything from a simple total to year-over-year and month-over-month growth, and the result reacts to every slicer on the page.

Prerequisites Two things first

  • The data is processed properly and ready for reporting, in Power Query, SQL or Python.
  • The data model is right. A bad model gives wrong results in every measure. The Power BI Basics guide covers keys, relationships and the star schema.

Syntax Anatomy of a measure

Total Sales = SUM(Sales[SalesAmount])
  • Total Sales is the measure name, and = starts the formula.
  • SUM is the function. The parentheses hold its arguments.
  • Sales is the table and [SalesAmount] the column the function adds up.

Core idea Calculated column or measure

Calculated columnMeasure
ComputedRow by row, when the data refreshesWhen a visual asks, for the cell it draws
StoredYes, as a new column in the tableNo, only the formula is stored
Reacts to slicersNo, the value is fixed per rowYes, every cell is recalculated with its filters
Use it forA value per row you want to group or filter by, such as a segmentTotals, ratios, growth, shares, ranks

Rule of thumb: if you will put it on an axis, in a slicer or in a row, make a column. If you will aggregate it, make a measure. The slide's mini challenge does both: a column Order value segment (under 1,000 is Low-value, otherwise High-value) and a measure Revenue on the line total.

Context The same measure answers differently in every cell

A measure is calculated inside the filters of the cell it sits in: the year on the axis, the territory in the slicer, the category on the row. CALCULATE changes that filter on purpose, which is why it appears in so many measures. Many wrong numbers come from a filter you did not know was active.

Advanced Time intelligence

FunctionReturns
TOTALYTD, TOTALQTD, TOTALMTDThe year-, quarter- or month-to-date value of a measure
SAMEPERIODLASTYEAR, PREVIOUSYEARThe same dates one year earlier, or the previous calendar year
DATEADDDates shifted by an interval: DATEADD(Dates[Date], -1, YEAR)
DATESYTD, FIRSTDATE, LASTDATEThe dates from the start of the year, the first date, the last date
DATEDIFFThe difference between two dates in the unit you choose

These need a date table: one row per day with no gaps, related to the date column of the fact table and marked as the date table.

Watch out Mistakes in a first set of measures

  • A ratio built from averages. The average of the ten territory order values is $7,641. The real order value is $3,491. Divide total revenue by total orders instead (Practice 2).
  • The wrong grain for an average. AVERAGE(Sales[LineTotal]) is $905 per order line, a quarter of the order value.
  • Growth on a part year. 2014 holds six months of data, so "2014 against 2013" can read -54.0% when like-for-like is +7.4% (Practice 3).
  • A date table with gaps or the wrong end date. Time intelligence reads the dates in the filter. The date table decides what "the same period" means.
  • A column where a measure belongs. A calculated column of revenue per row cannot respond to a slicer.
  • No check against SQL. Compare every new measure with a query you trust before it goes on a page.
