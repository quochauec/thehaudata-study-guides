Power BI Basics

How the Power BI suite fits together, how Power Query cleans data, and how a data model keeps relationships right. Practice uses the GlassDoor data-jobs files and AdventureWorks, with SQL checks for every step.

Power BI turns raw tables into a report in three moves: clean the data in Power Query, connect the tables in a data model, then visualise it. Most wrong numbers come from the first two moves. Test a relationship in tab 3.

Suite Three parts, one lifecycle

Power BI Desktop
  • A Windows application for data analysis
  • Where you clean, model and build reports
Power BI Service
  • An online (SaaS) platform for sharing and collaboration
  • Gateways connect it to data that stays inside your organisation
Mobile apps
  • Read the published reports on a phone or tablet

The usual path: connect to sources, build in Desktop, publish to the Service, share and read on web or mobile.

Desktop From data to insight in six stages

  1. Data sources. Cloud services, databases, Excel and CSV files, web APIs.
  2. Power Query. Import, transform and shape, clean and filter, combine.
  3. Data model. Relationships between tables, plus measures and columns.
  4. DAX. Calculations and business logic, such as CALCULATE(), SUMX() and FILTER(). The next guide covers it.
  5. Reports. Visualisations, formatting, slicers and filters.
  6. Dashboards. Publish, share and read on mobile.

Each stage has its own tools, and each one depends on the stage before it. A bad model breaks every measure built on top of it.

Power Query The data preparation engine

A graphical tool for transforming data without code. Its five parts: the ribbon, the queries pane, the current view (the data), query settings (the list of applied steps) and the status bar. Every click adds a step, and the steps replay when the data refreshes.

Simple jobs: remove a column, filter rows. Advanced jobs: merge, append, group by, pivot, unpivot.

Model Facts, dimensions, keys

  • A fact table holds transactions or events. It is large and keeps growing.
  • A dimension table describes something: product, customer, territory. It is smaller and changes less.
  • A primary key identifies one row and has no duplicates or blanks. A foreign key points to a primary key in another table.

Relationships One-to-one, one-to-many, many-to-many

  • 1-1: one row on the left matches one row on the right.
  • 1-M: one row on the left matches many on the right. Product to order lines.
  • M-M: many on both sides. Orders to sales reasons.

A relationship works only if the one side has unique keys. Test it with COUNT(*) against COUNT(DISTINCT key).

Power BI model Why relationships matter, and the star schema

Tables need direct relationships so that a filter on one table reaches the others (the job a JOIN does in SQL) and so that DAX measures such as time intelligence work. The slides recommend a star schema: fact tables in the middle, dimension tables around them.

  1. Pick the key columns on each side and give them the same data type.
  2. Decide the relationship (1-1, 1-M or M-M) from the data, not from the column names.
  3. Validate. Build a measure that uses conditions from more than one table and compare it with a number you trust.

Watch out Mistakes in a first model

  • A dimension with repeated rows. The GlassDoor company table has 672 rows but 432 companies. Related as it is, every posting matches several rows (Practice 3).
  • Placeholders read as data. The value -1 means unknown in several GlassDoor columns. Left in, it drags averages down (Practice 1).
  • Amounts at the wrong grain. An order total repeated on every order line inflates the sum. In AdventureWorks the subtotal summed over lines is 23.6 times the real one (Practice 4).
  • Trusting the auto-detected relationships. Power BI proposes relationships when you load tables. Open the Model view and check each one.
  • Mismatched key types. Text on one side and a number on the other will not relate. Fix the type in Power Query first.
  • Many-to-many as a shortcut. It usually means a dimension or a bridge table is missing.
