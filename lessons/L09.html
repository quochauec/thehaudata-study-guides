Customer Segmentation with RFM

Split customers into segments by Recency, Frequency and Monetary value, step by step in SQL. Practice runs on TheLook e-commerce data because the class Online Retail table is not in the workspace.

RFM scores every customer on how recently, how often and how much they buy, then groups them so each group gets the right treatment. Score a customer in tab 3.

What Customer segmentation

Divide the customer base into smaller, distinct groups. Examples: a bank priority programme, Shopee Gold, Silver and Bronze ranks.

Why Tailored actions

Different segments need different offers. Treating everyone the same wastes budget on people who would buy anyway and ignores the ones about to leave.

Model R, F and M

Recency
  • How recently the customer bought
  • Days between their last order and the snapshot date. Smaller is better.
Frequency
  • How often they buy
  • Number of distinct orders. Larger is better.
Monetary
  • How much they spent
  • Total spend. Larger is better.

Method Four steps in SQL

  1. R, F, M per customer. MAX(date), COUNT(DISTINCT order), SUM(amount). Recency = DATEDIFF(day, last_order, snapshot).
  2. Percentile of each metric. PERCENT_RANK() OVER (ORDER BY ...) gives each customer's position among all customers (0 to 1). Order Recency descending so recent customers rank high.
  3. Score 1 to 5. Cut each percentile into five bands: up to 0.2 is 1, up to 0.4 is 2, up to 0.6 is 3, up to 0.8 is 4, above is 5. Join the three digits into a code such as 555.
  4. Map to a segment. Join the code to a lookup table (score to segment), then count customers, orders and revenue per segment.

Limit Lifetime metrics hide movement

RFM computed over all time cannot show customers moving between segments. In practice you segment on a given period (monthly or quarterly) and compare periods to see the movement.

Watch out Mistakes in RFM

  • Direction of Recency. Small recency is good, but a high percentile should mean good. Sort Recency DESC in PERCENT_RANK so the most recent buyers get the highest percentile and score.
  • Ties break equal bands. In TheLook, 70% of customers have one order, so every one of them gets the same Frequency percentile. The scores end up 1, 4 and 5 only; scores 2 and 3 never appear (see Practice 3). Percentile bands assume the values spread out.
  • The snapshot date is a choice. The class key uses the latest date in the data. For live data use today's date, or every Recency shifts with each refresh.
  • Exclude cancellations and returns, and missing IDs. The class key filters Quantity > 0 and CustomerID != 'NULL' (the text 'NULL' stored as a value). A customer with no ID would become one giant fake customer.
  • Check the key's own typo. The reference file points to a table named customer_segment_FRM_temp in one place and customer_segment_RFM_temp in another. Use one name.
